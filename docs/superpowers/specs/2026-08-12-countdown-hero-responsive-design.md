# 倒计时头图响应式比例修复设计

## 目标

修复 `hero.countdownOverlay` 在约 375px 移动端仍沿用桌面高度和桌面内容尺度的问题，同时保持已经确认的 600px 桌面构图、可编辑内容、主题色绑定和邮件客户端降级能力。

## 根因

当前主视觉同时设置 `height:115vw`、`max-height:690px` 与 `min-height:600px`。在 375px 视口中，比例高度本应约为 431px，却被 `min-height:600px` 强制拉高。与此同时，61px 导航、67px/81px 标题、55px 面板上下内边距、120px Logo、200px 分隔图、四段固定间距和 43px CTA 都保持桌面值，造成移动端纵向比例失真和内容拥挤。

## 已确认方案

采用“桌面固定基准＋支持的移动客户端流式缩放＋旧客户端固定降级”的单模板方案，不使用媒体查询、JavaScript、Flex、Grid 或绝对定位。

### 桌面端

- 画布宽度保持 600px。
- 顶部导航保持 61px。
- 主视觉保持 600×690px，总高度保持 600×751px。
- 中央面板最大宽度保持 444px。
- 桌面端 Logo、分隔图、标题、补充文字、间距和 CTA 的视觉尺寸保持现状。

### 375px 移动端

- 顶部导航使用 `clamp()` 从 61px 流式缩放，375px 目标高度约 48px。
- 主视觉按 `115vw` 缩放，375px 目标高度约 431px；移除造成失真的 600px 最低高度，并以约 320px 设备对应的 368px 作为保守下限。
- 中央面板继续使用 `width:100%` 与 444px 最大宽度，在可用宽度内自然缩窄。
- 面板内边距、Logo、分隔图、倒计时标题、补充文字、四段间距和 CTA 使用各自的 `clamp()` 值同步收缩。
- 倒计时标题在 375px 目标下约为 44px/52px，保持两行构图；补充文字约为 12px/18px，允许自然换行。
- 375px 目标总高度约 479px，保持与桌面构图接近的纵横比例，同时给 CTA 留出稳定空间。

### 邮件兼容降级

- 模板继续保留 HTML `height`、`width` 属性与现有桌面内联值，作为 Outlook 等不支持 `clamp()` 或视口单位客户端的稳定降级。
- 维护源 CSS 追加同一 class 的流式声明；拼接器将其内联在固定值之后。支持的客户端采用流式值，不支持的客户端忽略无法识别的后置声明并保留固定值。
- 不放宽拼接器的禁用标签、禁用 CSS 或完整快照校验规则。

## 组件修改范围

- `component.template.v1.html`：为导航单元格、面板内容、四段间距、标题、说明、CTA 增加专用 class，并把主视觉最低高度修正为 368px。
- `component.styles.v1.css`：写入桌面上限与移动端 `clamp()` 流式值。
- `效果演示.html`：同步真实默认快照的最终内联结构。
- `COMPONENT_MANAGEMENT.zh-CN.v1.md`、Skill 交互 reference：同步桌面和 375px 目标尺寸及降级说明。
- 不修改内容 Schema、默认文案、图片、链接、颜色绑定或 Shopify/Omnisend 安全边界。

## 测试与视觉验证

1. 先更新组件契约测试，要求不再出现 `min-height:600px`，并要求主视觉 368px 下限和所有已确认的响应式 class/`clamp()` 声明；确认测试因旧实现失败。
2. 最小化修改模板、CSS、演示和文档，使定向测试通过。
3. 运行全部 Node 测试与 Campaign 结构校验。
4. 重新生成 `countdown-hero.local-preview.html`。
5. 浏览器允许访问预览时，检查 600px 与 375px 两个视口的页面身份、非空内容、控制台、完整截图、换行、裁切、间距和溢出。若 `file://` 自动化仍被安全策略阻断，明确记录为视觉 QA 阻塞，不能把源级检查冒充浏览器视觉通过。
