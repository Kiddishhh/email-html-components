# Campaign Skill 本地可视化编辑器设计

## 目标

让 `build-omnisend-campaign-draft` 被调用时自动打开本地编辑器。编辑器只使用当前 `组件清单.json`、Campaign 结构契约与交互契约，不再依赖已移除的旧组件库。

## 范围与边界

- 仅显示并编辑六个固定 Campaign 区段：首图、六宫格、整图、赠品、地址、页脚；可选注册组件不进入 Campaign 编辑器。
- 提供 Campaign 名称、Subject、Preheader、正文背景色、操作色和组件内容/设置的本地草稿编辑。
- 同屏提供 600px 桌面端和 375px 移动端预览；样式选择直接嵌入各组件实际的 `效果演示.html`。
- 本地上传的图片只生成浏览器预览 URL 与草稿元数据；不上传 Omnisend、Shopify 或任何第三方，也不生成可发送邮件。
- 编辑器保存可恢复的本地草稿，并能调用既有构建器生成本地预览；最终邮件生成、哈希确认和 Omnisend 草稿上传仍严格沿用既有 Skill 安全门。

## 架构

新增 `scripts/start-campaign-editor.mjs` 作为唯一入口。脚本先运行现有契约校验器，再在 `127.0.0.1` 启动本地 HTTP 服务并输出编辑器 URL。它服务静态编辑器资源，并暴露受限的本地读取/保存接口：注册表、六区段结构、可用样式、组件 Schema、组件演示和命名草稿。

编辑器前端分为三栏：活动设置与区段列表、当前区段字段面板、双画布预览。前端不得直接请求 Shopify 或 Omnisend；所有数据仅来自本地接口和受验证的组件文件。

Skill 工作流的第一步改为启动该入口并在 Codex 内打开所输出的本地 URL；若端口占用或契约校验失败，明确显示错误并不创建草稿。

## 数据与安全

草稿写入 `campaign-drafts/<safe-slug>/project-state.v1.json`。保存前校验路径、JSON 结构和图片类型；禁止通过 API 写入工作区以外的路径。图片二进制保存在对应草稿资源目录，最终上传仍仅可由既有固定上传脚本在最终确认后执行。

任何编辑器保存、预览或关闭都不得改变 Campaign 的最终确认状态，也不得创建、更新、发送、排期或发布 Omnisend Campaign。

## 验证

- 为启动脚本增加单元测试：通过契约校验、拒绝无效注册表、仅绑定 loopback 地址、打印可访问 URL。
- 为本地 API 增加测试：只返回六个区段、拒绝路径穿越、草稿的读取/保存可恢复。
- 为编辑器静态页面增加契约测试：包含 600px/375px 预览与本地上传控件，且不含远程服务调用。
- 保留并运行全部现有组件、Skill 和构建器测试。
