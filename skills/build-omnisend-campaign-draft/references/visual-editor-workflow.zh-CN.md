# Campaign 可视化编辑器

## 启动与会话

制作/编辑邮件请求由邮件应用管理skill打开编辑器供用户手动操作。先运行`node skills/build-omnisend-campaign-draft/scripts/resolve-campaign-editor.mjs`，有当前回环URL时追加`--url`。该脚本只读检查4173–4205端口并比对当前项目目录和默认值，返回`ready`直接打开，`start-required`使用返回的空闲`startPort`运行启动命令。它不会创建/修改草稿或关闭旧服务。

```bash
node skills/build-omnisend-campaign-draft/scripts/start-campaign-editor.mjs 4173
```

打开 `http://127.0.0.1:4173`。本地草稿、上传回执、预览和图片缓存只在当前编辑器运行期保存，关闭或重启服务即清理；只有手动保存的模板及其专属图片位于被忽略的 `campaign-drafts/editor-templates/`。两类存储均不保存 API Key。

组件目录与默认值在服务启动时读取；代码中新增组件或更新默认值后，只刷新旧服务的网页不会刷新这份缓存。先处理未保存草稿，再重启服务；也可将启动命令末尾端口改为一个空闲端口，保留旧服务。新实例使用该服务加载的默认值，旧草稿和已保存模板不会自动换成新的默认内容。

## 当前操作流程

1. 填写邮件名称并新建草稿。
2. 左侧可以选择分类与样式，也可以输入关键词搜索中文名、分类、componentKey 或变体。缩略图来自真实默认组件预览；点击卡片选择，再点“添加此组件”。组件来自 `组件清单.json`，可自由添加、重复、拖拽排序或删除；删除后再添加的实例编号不会与现存实例冲突。
3. 选中结构项后，中间预览将同一组件实例定位到预览区顶部，并显示短暂描边；描边不会进入导出 HTML。
4. 右侧仅显示该组件开放的内容与设置字段。每段可编辑文案下可展开“文字样式”，设置字体、字号、字重、颜色、行高、字间距、上下留白及可用的对齐，或恢复默认。修改字段或文案样式会撤销该实例的确认状态并自动刷新预览。
5. 在 600px 桌面模式和 375px 移动模式分别检查。窄屏编辑器按组件库、预览、设置面板的顺序单列显示，所有操作保持在当前视口内。
6. 等状态显示“已保存到当前会话”后逐个确认组件；所有组件确认后，当前草稿自动标记为已确认，导出/上传按钮可用。上传准备阶段绑定 HTML 哈希。内容、设置或图片变化撤销该组件及整封确认；排序或删除组件后，全部剩余组件恢复为“待确认”，逐个重新确认即可继续导出/上传，无需人为修改文案。空邮件不可确认。界面“已确认”不表示字段不可编辑。

## 保存状态与重试

状态栏区分待保存、正在保存、已保存和保存失败。字段修改绑定原草稿、按实例合并并串行提交，较早响应不会覆盖继续输入的新值。失败修改保留在待保存队列，点击“重试保存”；依赖操作会先等待保存，失败时停止。结构修改、切换草稿、导入及输出请求期间会暂时保护编辑区，普通自动保存期间仍可继续输入。仍有未保存修改时，离开页面会触发浏览器提示。

“已保存到当前会话”仅指本机服务当前运行期。刷新/关闭服务后的持久恢复未在本轮引入；需要长期保留仍使用模板。不要把编辑器会话保存状态当成 Omnisend 保存成功。

## 文案样式

设置只覆盖当前组件实例的对应文案；默认标题及商品名为 Georgia、备用 serif，其他文案为 Verdana、备用 sans-serif。手动字体覆盖默认，恢复默认回到该字体规则；其他未修改项继续使用组件原样式。上下留白保留原有分隔行和左右间距；清空单项恢复这一项，“恢复此文案的默认样式”清空全部覆盖。有效设置自动保存，输入中的色号/数字保留焦点和原始值。保存为模板时包含覆盖值；导出/上传继续使用原有流程。详见[文案独立样式](text-style-controls.zh-CN.md)。

## 商品卡分组

多商品组件的内容字段按“顶部文案 / 商品 1–6 / 底部 CTA”折叠展示；支持逐格导入的按钮位于对应商品面板内。分组保留所有既有字段、白名单、素材、链接和样式，不改变导出内容。颜色设置继续独立展示。

## 链接与 UTM

顶部“链接 / UTM”打开实际渲染链接清单：图片链接、CTA、固定页脚和退订令牌都可检查；被关闭的导航不列入清单。链接按模板内实际来源字段对应，不能仅凭地址相同把其他商品槽位合并；本地图片源不是链接，不参与 UTM。可编辑链接可定位到字段，固定链接只定位组件。

1. 勾选目标 HTTPS 链接，或点击“勾选可编辑 HTTPS 链接”。固定链接、mailto、tel 和退订令牌不参与批量修改。
2. 填写 utm_source、utm_medium、utm_campaign、utm_id、utm_content 或 utm_term；空白保留原值。
3. 点击“预览 UTM 修改”，检查逐字段的原/新地址。非 UTM 参数（如折扣码）和 URL 片段保留。
4. 点击“应用已预览修改”才写入。一个字段同时用于图片和 CTA 时一起更新；重复链接去重为字段修改。关闭预览不会改变内容。
5. 等待保存完成，受影响组件重新确认。若保存失败，修改仍保留在队列，关闭清单后重试保存。

该清单验证实际生成的 href，不执行远程跳转/落地页连通性检查，也不修改固定组件模板。

## 模板

顶部模板栏支持保存模板、选择模板继续编辑和删除模板：

- 保存模板记录当前画布、组件顺序、完整 `content`/`settings` 快照；若模板使用本地上传图片，会复制为该模板专属图片，可自定义名称。
- 同名保存必须先确认覆盖。
- 选择模板会创建一份新的可编辑草稿，不会回写模板；组件确认、整封确认、内容哈希、输出路径和 Omnisend 状态均重置。
- 删除模板会删除模板记录及其专属图片；由模板创建的当前编辑草稿仍可继续编辑到服务关闭。不会删除任何组件目录内的素材。
- 多个新版服务可以共用模板目录。保存、覆盖、删除和从模板创建草稿使用同一个 `.templates.lock` 跨进程锁；重名判断基于锁内重新读取的记录。模板列表接口每次读取最新磁盘状态，另一个服务保存的模板会在刷新列表后出现，删除的模板不会因旧服务再次保存而复活。
- 模板记录采用同目录临时文件加原子替换，避免读取半写入的 JSON。锁最多等待 5 秒，超时后本次操作报错，稍后可重试；不会超时强占另一服务的锁。若服务异常退出留下锁，先确认并停止所有使用该目录的编辑器，再移除 `campaign-drafts/editor-templates/.templates.lock` 后重启；不能在仍有模板操作运行时删除锁。
- 首次升级到此修复版本时，先妥善保存旧会话需要保留的草稿，再重启旧服务。旧进程仍执行旧代码，不参与新锁；只刷新网页或另开一个新版端口不能使新旧服务安全共写模板。

## 组件编辑

- 四款头图提供“显示顶部导航栏”复选框。关闭时从生成 HTML 移除导航结构和高度；再次开启时恢复该实例保存的文案、链接和颜色。
- 颜色字段提供色块和 `#RRGGBB` 输入。只有完整六位色号会写入组件快照。
- 图片字段可以填写公开 HTTPS URL，也可选择本地 PNG、JPEG、WebP 或 GIF 进行预览；单文件不超过 5 MB。
- `collection.saleGrid6` 支持从 Freshine Page、已上线 Collection URL，或 Shopify 后台 Collection handle 只读导入六件商品。后台 handle 仅作为数据源：六张商品卡保留 Shopify 返回的商品公开链接，整体 CTA 保持当前组件设置，不会指向未上线 Collection。
- `collection.saleGrid6WithTitle` 为逐格导入的标题款六宫格：分别使用“导入商品 1–6”输入 Freshine 商品 URL。导入只更新当前格的商品名、首图、Alt、链接和折扣，不影响其余五格、标题、副标题或 CTA。
- `collection.curtainPromotionCard` 与 `collection.curtainPromotionCardNoTitle` 支持从 Freshine 商品 URL 只读导入一个商品。导入不会覆盖 CTA 文案、顶部活动文案或配色。
- `collection.saleGrid4WithTitle` 的选择路径为“活动商品组件 → 四宫格折扣推荐（标题款）”。支持24项内容、5项颜色与4个逐格商品导入按钮；默认折扣依次为左上30%、右上40%、左下35%、右下50%。商品与底部CTA默认带`utm_source=omnisend&utm_medium=email&utm_id=cover-rc`，APPLY DISCOUNT指向Roman Shades集合页。逐格导入会覆盖该格的图片、Alt、折扣、商品链接和链接文字，导入后应检查UTM；不改其他卡片或底部CTA。
- `collection.sceneSaleGrid4WithTitle` 的选择路径为“活动商品组件 → 四宫格场景折扣（标题款）”。支持22项内容、6项颜色与4个逐格商品导入按钮；无底部CTA。逐格导入更新指定卡片的图片、Alt、链接、折扣和商品名称，并自动写入cover-rc UTM；不改其他卡片、顶部文案或颜色。
- `collection.productGrid4NoSidePadding` 的选择路径为“活动商品组件 → 四宫格商品推荐（无左右边距）”。支持22项内容、5项颜色与4个逐格商品导入按钮；600px 下四张商品图为289×361px、列间22px，375px下按比例缩放。逐格导入仅更新指定卡片的图片、Alt、链接、折扣和按钮文字，不改其他卡片、顶部文案或颜色。

## 导出 Omnisend HTML

“导出 Omnisend HTML”要求所有组件已确认。它仅执行以下操作：

1. 先对待上传 HTML 执行共用安全校验，再上传尚未缓存的本地图片；
2. 将 `asset://` 替换为公开 HTTPS URL；
3. 重新校验静态邮件 HTML；
4. 把完整 HTML 写入剪切板。

该流程不会创建、更新或发送 Campaign 或 Draft。图片缓存按图片字节 SHA-256 与 API Key 的不可逆哈希隔离账户，不保存 API Key，并由默认导出适配器透传，在同一编辑器会话的不同草稿间复用；关闭服务后清理。若剪切板被浏览器拒绝，界面显示只读 HTML 供手动复制，不重新上传图片。

## 上传 Omnisend 草稿

“上传 Omnisend 草稿”要求所有组件与整封邮件均已确认，并在一个对话框中收集 Campaign 名称、Subject、Preheader 和一次性 API Key。

- API Key 只存在于当前浏览器请求和本机进程内存，结束后立即清空。
- 先精确检索同名 `draft`；多个结果更新最近更新的一封，没有匹配才创建 Draft。
- 新建和更新后均回读 Campaign 与 Email Content，验证 `status: draft`、内容 ID、退订令牌，以及实际 HTML 正文的规范化可见文字、文字顺序、公开 URL 和图片 Alt。更新时只校验实际替换的 HTML 区块；新建时可按文档顺序合并平台拆分的 HTML 区块。响应元数据中的相同文案或链接不能代替正文。
- 回读不符会报错且不产生成功回执，不自动补写或重新创建。若远端已经接受写入，验证失败不表示已撤销远端写入；应先检查该 Draft。回执记录本地 HTML、远端 HTML、响应和规范化文字的独立哈希；允许正常空白及非内容属性变化，不承诺 HTML 字节或收件箱视觉一致。
- 不提供发送、排期或发布操作。


模板反复复用时，上传图片使用稳定的 `assetId + 扩展名` 文件名。已有模板中历史累加的文件名前缀会在复制到新草稿时收敛，随后保存即使用稳定名称；原图字节与组件图片引用不变。

导出/上传会精确替换完整图片 ID，名称有前缀关系的素材不会串图。Draft 回读允许等价的命名/数字 HTML 实体序列化差异，但真实正文变化仍会报错；无需因此重复提交语义相同的内容。


### 模板恢复、并发和回读

模板现在先完成独立版本的图片写入，再切换索引。保存失败可重试，旧模板仍可读取；提交后的无引用文件清理失败会留待下次模板保存/删除处理，不误报保存失败。

保存、使用或删除模板后，锁会先改名释放，再清理残留目录。清理失败不改变实际结果；锁本身持续无法释放时，成功回执带 `template-lock-release-pending` 警告，模板状态区保留成功提示并显示恢复说明。先解除磁盘或权限问题，再在当前编辑器重试模板操作；服务会核对目录身份，只重试释放自己上次操作遗留的锁。若持续提示忙，或服务进程已退出，先停止全部使用该目录的编辑器，再按上文移除残留锁并重启；不要因为收到警告就重复保存已完成的模板。

若在操作开始前读取锁身份失败，本次操作不会执行，刚创建的空锁会被清理；解除磁盘故障后可直接重试。若错误同时提示 `empty lock cleanup failed`，表示空锁清理也未成功，应先停止全部编辑器再按上文恢复，不能直接删除仍有操作使用的锁。

同一草稿的请求在收齐请求体后排队执行，修改与确认、预览、模板保存、导出/上传共享顺序。慢请求不会覆盖已保存的其他字段；同一字段多次修改仍以后执行的请求为准。前端原有保存等待和失败重试操作不变。

上传回读会核对链接、图片 Alt/所属链接、背景、Outlook VML 点击目标，以及图片/背景所属内容块；把图片或背景移到另一张卡片，即使文案和 URL 相同，也不能作为正确回读。URL 仅出现在注释、元数据或 CSS 引号字符串中不算成功，真正 `url('…')` 的引号参数仍有效。无害包装和表格结束标签省略可通过，URL 重写或节点关联改变则报告失败，按原只读恢复流程处理，不自动重复上传。

平台仅增加 `display:inline` 的局部包装，或将 Alt 等引号属性里的 `>` 转成 `&gt;`/数字实体时，可以通过回读；不会因此把图片判为换块或把属性误当成正文。真实正文、Alt 和图片/背景归属变化仍会失败。

回读同时检查真实词间空白：只增加 span、内联包装或注释不会制造空格，`Save20%` 和 `Save 20%` 仍是不同文案。正文和链接文字使用同一提取规则；把原文藏进 script/style/template/title、hidden 或 display:none 区域不能算作保留了正文。普通邮件与 Outlook 分支分别验证。此规则只用于读取比较，不改写邮件样式或上传内容。

回读中的 center 等默认块级元素会形成文字分隔；显式 display:inline 仍按行内处理。平台省略段落结束标签时，后续可见段落的正文、链接和图片继续接受校验，不会错误继承前一段的隐藏状态。title 内即使出现看似闭合标签或图片的文字，也不会影响外层内容。

若省略段落结束标签同时跨越未关闭的粗体、链接等格式化标签，会提示 `unsupported implicit paragraph closure`。这表示静态校验无法确认 HTML 重建后的显示或链接关系，应先检查远端内容并按只读恢复流程处理，不要直接重复上传。

正文回读和更新只定位真实布局内容块；metadata 内的 htmlCode 不算正文。若只有元数据含完整邮件，更新会在写入前拒绝；回读也不会报告成功。有效正文旁存在同名元数据不影响验证，更新保留元数据、样式和节点 ID。

title 的 NBSP 等非 ASCII 字符不会被误当成标签分隔；无法可靠解析的结束标签或嵌套 form 会分别提示 `unsupported ... closing tag`、`unsupported nested form`。这些情况沿用原有失败及只读恢复流程，不自动重复上传，也不代表远端先前已接受的写入被撤销。
