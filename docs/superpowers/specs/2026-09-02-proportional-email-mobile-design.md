# 全库邮件组件等比移动端设计

## 目标

将 `组件清单.json` 中所有当前登记组件统一为 600px 桌面基准、375px 等比移动端渲染，避免任何同一组件内的文字、行高、固定几何、图片区域或留白只缩放一部分。

## 规则

- 邮件结构保持 table + inline CSS；不引入媒体查询、Flex、Grid、脚本或全局样式依赖。
- 桌面声明必须在前，移动端渐进覆写紧随其后：`property:Npx;property:min(Npx,N/6vw)`。600px 时保持原值，375px 时为原值的 62.5%。
- 对有视觉尺度的非零 `font-size`、像素 `line-height`、固定 `width`/`height`、`padding`、`margin` 和 `border-radius` 使用同一等比覆写。百分比、`auto`、`0`、1px 描边与 `font-size:0` 占位符不缩放。
- 已通过百分比流式收缩的 `width:100%` / 百分比宽度保留原行为；纯整图组件继续使用流式图片 `width:100%;height:auto`。
- 不改变已确认的列数、图片比例、链接边界、文案、颜色、组件 key 或编辑器字段。移动端不自动改单列。
- `效果演示.html` 必须与对应模板的移动规则一致。

## 验收

- 全部已注册模板与演示文件通过静态移动端契约：不存在缺少 `min()` 等比覆写的受控像素视觉尺寸。
- 600px 仍保留桌面尺寸；375px 的受控尺寸按 62.5% 收缩，且模板不出现横向溢出规则退化。
- Skill 的新组件规范明确该规则、例外、同步面与验证命令。
- 全量测试、组件契约验证和 `git diff --check` 通过；本地验证与真实 Omnisend/邮箱客户端验证分开说明。
