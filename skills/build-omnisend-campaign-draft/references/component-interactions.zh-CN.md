## 1. 通用规则

- 每次只询问一个组件的一组紧密相关字段。
- 展示建议值不等于采用默认值；需要用户明确使用或输入。
- 每个组件确认前生成桌面端与约 375px 移动端预览。
- 组件确认后锁定。修改指定组件时不改变其他组件。
- 只开放文案、图片、链接、操作色、背景色等常用设置；不向用户暴露完整 CSS。
- 正文组件背景色只写入该组件的 `settings`；邮件 `canvas` 与外层背景保持其原有颜色。页脚背景色始终独立设置。

## 2. `hero.promotionalOverlay` 促销悬浮首图

### 图片

默认图通常只作视觉参考。若用户明确选择使用默认主图，可把该本地组件资源用于当前本地预览；最终上传 Omnisend 前必须上传为公开 HTTPS URL。否则允许来源为本地上传、Shopify Files、公开 HTTPS URL。

提示用户：

- 建议比例 `600:722`；
- 建议最低尺寸 `1200×1444`；
- 使用无文字、Logo、按钮或面板的干净底图；
- 顶部中央保留 Logo 安全区；
- 底部中央保留半透明文案面板安全区；
- 主体人物或商品尽量位于中部偏左或偏右，避免被面板遮挡。

检查图片尺寸与比例；不合适时建议裁剪或更换。自动生成 Alt，并让用户选择采用或修改。

### Logo 样式确认

首图交互顺序固定为：主视觉图片 → Logo 样式确认 → 首图完成卡片。默认 Logo 样式是白色 FreShine 字标、`#A79689` 圆形背景与 70% 透明度；保持旧版圆形 106px、字标 80px，不改变原有布局尺寸。

生成一张可编辑的 Logo 设置卡片，并同时展示桌面端预览和 375px 移动端预览；卡片须注明 Outlook 等不支持 RGBA 的客户端使用 `#A79689` 实色降级。设置卡片按顺序显示 Logo 图片、Alt、点击链接、圆形背景色和透明度，所有默认值在确认前均可编辑。默认 Logo 图片仍使用现有白色 FreShine 字标，默认点击链接为 Freshine 首页。只询问一次“是否采用默认 Logo 样式”。采用时写入当前卡片的完整 Logo 内容与设置快照。

用户替换 Logo 图片时，接受公开 HTTPS URL 或用户明确提供的本地 Logo 文件；本地 Logo 只用于预览，最终确认后由固定脚本上传并替换为公开 HTTPS URL。圆形背景色只接受新 `#A1B2C3` 格式色号，透明度只接受 0–100%。把百分比除以 100 并保留两位小数，确定性生成 `rgba(r, g, b, a)`；实色值始终作为 Outlook 降级色。106px 圆形和 80px 字标尺寸保持固定，不纳入编辑。修改后重新展示同一设置卡片、桌面端预览和 375px 移动端预览并再次只询问一次。Logo 样式确认不替代首图完成卡片确认。

### 顶部促销条

把 `promotion.text` 与 `promotion.linkText` 放在同一次交互中，展示建议后询问采用或同时修改。链接单独询问；只允许新 HTTPS URL 或首页 `https://freshinelife.com/`，不从 Shopify 商品数据猜测。

### 活动文案

只读拉取在线主题首页 `templates/index.json`，仅从唯一启用 `slideshow-v2` 的可读 slide 建立候选；不读取 Shopify 菜单或全量 Page。候选编号仅展示活动名与 slide 链接的公开 Page URL；一个候选时只询问是否采用，多个候选时只让用户选编号。

从用户选定的首页 slide 读取并映射：

- `slideshow-v2` 的 `subheading` → `hero.eyebrow`（首行：活动名称）；
- `slideshow-v2` 的 `heading` → `hero.title`（第二行：折扣消息）；
- `slideshow-v2` 的 `description` → `hero.subtitle`（第三行：补充说明）。

选择后才只读查询该 slide 链接的一个 Page 模板，以取得首个启用 `products-grid-v2` 的推荐 Collection；随后重新拉取首页与该模板并验证选定 slide 未变化。选定后展示导入的 `subheading`、`heading`、`description` 与推荐 Collection，供用户了解当前来源；这一步不新增确认。它们仍与主视觉图片、顶部促销条、CTA 等一起出现在首图完成卡片中；Logo 样式已在前一步单独确认，首图完成卡片仍需一次最终确认。保存 Page URL、模板、首页 Section ID、读取时间和确认哈希。

### CTA 与颜色

CTA URL 固定为选定首页 slide 链接的活动页，并展示完整 URL 和用途说明。常规交互只询问：使用 `SHOP NOW`，或输入新的按钮文字。

操作色和背景色按全局规则继承或覆盖。背景色只影响画布与图片失败时的回退区域，不替换主图和 Logo 白色条形区域。

## 3. `collection.saleGrid6` 六宫格夏季促销

### Shopify 默认注入

编辑器按钮“shopify商品导入”接受完整活动页或 Collection URL。`https://freshinelife.com/pages/<handle>` 会读取该 Page 的线上主题模板，按模板顺序找到首个启用 `products-grid-v2` 的 Collection；`https://freshinelife.com/collections/<handle>` 直接作为商品来源。两种路径均按来源当前排序取前六个商品，CTA 始终保留输入链接。不要逐商品询问是否采用；先完成默认注入，再用当前设置卡片展示。

每个商品注入：

- `media(first: 1, query: "media_type:IMAGE", sortKey: POSITION)` 的首个 `MediaImage.image.url` → 商品详情页排序中的第一张图片；
- 首个 `MediaImage.alt` → Alt，缺失时根据商品标题生成；
- `onlineStoreUrl` → 该商品图片的独立 `image.clickUrl`；
- 首个可售变体的 `price` 与 `compareAtPrice` → 折扣标签计算输入。

不得使用 `featuredImage`、变体图或视频缩略图替代商品详情页第一张图片；首个图片媒体缺失时停止并标记具体商品。所有商品图片必须分别链接到自己的商品详情页，不能共用 Collection 链接。`onlineStoreUrl` 为空时使用 `https://freshinelife.com/products/{handle}` 并标记为回退链接。

### 折扣标签

严格匹配 Shopify 当前主题规则：优先采用 `selected_or_first_available_variant`；当 `compareAtPrice > price` 时计算：

`round((compareAtPrice - price) × 100 ÷ compareAtPrice)`

输出 `SAVE xx%`。无有效 `compareAtPrice` 时不虚构折扣，渲染时隐藏标签并要求 Schema 允许空值。

### 标题与说明

必须主动向用户收集标题和说明文案，不得自动采用默认值。可以根据选定活动主题生成推荐，但只有用户明确采用后才能注入。

### 默认注入内容卡片与 CTA

使用“shopify商品导入”后，底部 CTA 使用并保留用户输入的完整 Page 或 Collection URL；未导入时保留组件完整快照中的 CTA。`SHOP NOW` 是 CTA 的默认文字。这两项都是当前设置，不是不可修改的固定值。

默认注入完成后，用一张“当前设置”卡片展示。卡片必须同时展示六个商品图片、Alt、商品详情链接、折扣标签以及 CTA 默认文字和完整 URL；标记回退链接和隐藏折扣标签的商品。提示用户查看卡片并主动指出需要修改的项目；不逐项追问，用户未提出修改的内容保留当前设置。

标题和说明不属于默认注入内容，仍须按上节规则主动收集。

### 颜色

只使用一个操作色，同时控制六个折扣标签和 CTA 按钮的主题色；不为各标签或按钮分别询问颜色。背景色与操作色分开，是一项需要单独处理的设置。

对操作色和背景色分别判断开场设置：

- 如果开场未设置对应的全局统一色号，则对本组件的操作色和背景色分别单独询问。
- 如果开场已设置对应的全局统一色号，则将继承色作为本组件的当前默认值，在当前设置卡片中展示，不另外追问。只有用户主动提出修改时才覆盖继承色。

所有颜色展示仍须包含完整 `#RRGGBB`、中文近似描述和真实色块。

### 完整确认

所有内容与颜色形成完整快照后，同时展示当前设置卡片、桌面端预览和约 375px 移动端预览。三项都成功生成后，只询问一次用户是否确认本组件。

用户主动指出需要修改的项目时，只更新指定字段，然后重新生成上述三项内容并再次询问。只有用户明确确认后才锁定 `collection.saleGrid6`；未确认、修改中或预览失败时均不得锁定。

组件固有布局保持桌面端两列、移动端居中单列，不作为可选交互。

## 4. `image.clickableFullWidth` 可链接整图

### 图片、Alt 与完成卡片

整图主要可用于展示客户评论、评论截图或评论拼图，但不限制为唯一用途。默认图在 `600px` 画布全宽、零外边距显示；当前评论图为 `1200 × 2186px`，桌面端约为 `600 × 1093px`，并会在约 `375px` 移动端缩放为约 `375 × 683px`。完成卡片提示图片内小字的移动端可读性；仅当用户主动提出替换时，才收集公开 HTTPS 图片链接或本地图片路径。

整图点击跳转链接默认 `https://freshinelife.com/`，不单独追问；在完成卡片中展示，只有用户主动提出时才修改。使用当前背景色与外边距生成完成卡片、桌面端预览和约 `375px` 移动端预览；用户只需一次确认。主动修改时只重开本组件并重新生成卡片与预览。

## 8. `hero.countdownOverlay` 倒计时头图

### 尺寸、内容与图片

组件使用 `width:100%;max-width:600px`：桌面画布固定在 600px 上限，移动端只收窄宽度。主视觉沿用默认背景 1200×1443 的真实宽高比；桌面总画布约为 `600×778px`，其中顶部为 56px 导航，主视觉约为 `600×722px`。提示用户提供适合完整铺满主视觉的 `600×722px` 背景图；高分辨率版本保持 `1200×1443px`，背景不含导航。导航下方的跨两列外壳保持 table-cell，背景放入内部单列 `td`；内层背景使用 `height:120vw`、`min-height:560px`、`max-height:722px` 和 `display:block`，跨列外壳不得使用 block。600px 桌面主视觉稳定为 722px；375px 移动端主视觉稳定为 560px，含导航总高约 616px。背景使用 `cover` 与 `center center`，移动端允许可控的左右裁切。中央面板桌面最大宽度为 460px、最大高度为 520px，内容垂直居中；约 375px 移动端仍由两侧各 10px 留白限制为约 355px 宽，面板以 `86.67vw` 收窄到约 325px 高，内容较多时允许由自然高度撑开。内部使用 28px 24px 内边距和 8/14/22/22px 四段间距；Logo 为 108px、分隔图为 220px、CTA 为 200×44px。左侧导航文案使用 14px/20px，在窄屏允许自然换成两行但导航仍保持 56px。不能识别流式高度的邮件客户端保留 `height="722"` 作为稳定降级。接受公开 HTTPS URL 或用户明确提供的本地图片路径；本地图片只用于预览，最终 Omnisend HTML 前必须由固定上传脚本替换为公开 HTTPS URL。

直接载入组件默认完整快照，不从 Shopify slide 导入文案。倒计时标题只使用一个可编辑字段 `countdown.title`，默认值为 `Only 3 Days Left`；标题框固定为 280px 宽并使用正常空白自然换行，使默认文案显示为第一行 `Only 3`、第二行 `Days Left`，模板不得插入固定换行标签或拆分字段。桌面与移动端均使用 Lora Regular，字重 400、字号 50px、行高 64px、字间距 0px、居中对齐；下方补充文字均使用 Montserrat 14px/21px。标题、补充文字、顶部导航文字、`SIGN UP`、`SHOP NOW`、各自链接、背景图、Logo 和分隔图均作为当前设置展示，用户主动提出时才修改。默认导航、Logo 与 CTA 链接为 `https://freshinelife.com/`。

### 绑定配色

右侧 `SIGN UP` 区域使用独立的 `color.navigationRight`，`SHOP NOW` 按钮使用 `color.theme`。参考图初始默认值为 `color.theme: #725A4B`、`color.navigationRight: #725A4B`、`color.navigationLeft: #97866D`，配色来源记录为 `reference-default`；载入默认完整快照时不得重新计算并覆盖这些颜色。

用户主动修改主题色且没有左侧覆盖值时，Skill 才运行 `scripts/derive-countdown-theme.mjs --theme <#RRGGBB>`，对每个 RGB 通道按主题色 35%、浅色基准 65% 计算并四舍五入，浅色基准固定为 `#F4F1EC`，得到协调的 `color.navigationLeft`，并把来源记录为 `derived`。

用户可单独修改左侧或右侧导航色。存在左侧覆盖值时，运行脚本时增加 `--navigation-left <#RRGGBB>`，记录来源为 `user-override`；随后即使修改 CTA 主题色也保留该左侧色，直到用户明确要求恢复自动配色。恢复时移除覆盖值并重新计算。所有色号只接受完整 `#RRGGBB`。

### 完成确认

用一张当前设置卡片展示全部默认注入内容、`color.theme`、`color.navigationRight`、当前左侧导航色及其来源，并同时生成桌面端和约 375px 移动端预览。只进行一次组件完成确认，不为字体、自动配色、默认链接或单个默认字段增加确认。用户主动提出修改时只更新指定字段、重新执行必要的配色计算并刷新同一张卡片和两种预览。

## 9. `hero.countdownOverlay2` 倒计时头图2

### Shopify 活动导入

沿用促销悬浮首图已锁定的只读流程：首先运行 `list-sale-activities.mjs`；一个活动时只问是否使用，多个时只让用户选编号。选定后立即运行 `fetch-sale-activity.mjs`，重新验证首页 slide 与活动 Page 快照，并锁定推荐 Collection。

字段映射固定为：

- `slideshow-v2.subheading` → `hero.eyebrow`（第一行活动名称）；
- `slideshow-v2.heading` → `hero.title`（第二行折扣消息）；
- `slideshow-v2.description` → `hero.subtitle`（第三行补充说明）；
- 选定活动页 URL → `hero.cta.url`。

展示导入的三行文案、活动页 URL 和推荐 Collection，但不新增一次文案确认。六宫格阶段直接复用该锁定快照，不重复读取或询问。

### 主图收集与裁切

必须主动进入主图收集，不因组件有默认图而跳过。先说明组件画布为 600px，图片与图下文案区组成宽度 90%、最大 540px 的内层卡片；图片使用 `1:1` 比例，桌面端显示为 `540×540px`，约 375px 移动端显示为 `337.5×337.5px`。再提示建议源图 `1200×1200px`，并提醒主体与关键内容位于中央安全区。随后只提供三种选择：使用设计稿裁切的组件默认图、提供本地图片路径、提供公开 HTTPS 图片 URL。检查图片尺寸和实际内容，根据图片生成 Alt 建议并在完成卡片展示。

比例不符 `1:1` 时，先说明将居中裁切，再运行 `scripts/prepare-countdown-hero-2-image.mjs --input <本地图片> --output <独立衍生图>`。脚本固定生成 `1200×1200px` 衍生图，不覆盖原图。公开 HTTPS 图先只读下载到新临时文件后再处理；读取或处理失败时停止生成确认预览。主图与图下文案区始终等宽并置于组件背景色之上，固定保留左右和底部背景留白，不依赖邮件客户端 `object-fit` 裁切。
